【 جديد في v14 / Nouveau dans v14 — حماية حد اتصالات MongoDB 】
✔ خفض استهلاك اتصالات قاعدة البيانات بنسبة كبيرة (المشكلة: تجاوز الحد
  المسموح للاتصالات في MongoDB Atlas وأدى لتوقف الموقع): كان كل نسخة
  دالة على Vercel تفتح تجمع اتصالات يصل إلى 15 اتصالاً، والاتصالات
  الخاملة تبقى مفتوحة في Atlas لفترة، ومع تعدد الزوار تراكمت حتى
  تجاوزت الحد. الحل ثلاثي الطبقات، دون أي تغيير في المظهر أو الوظائف:
  ① تجمع اتصالات أصغر وأكثر نظافة: 15 ← 5 اتصالات كحد أقصى لكل نسخة
     مع إغلاق الاتصالات الخاملة بعد 30 ثانية (maxIdleTimeMS) — فتنخفض
     اتصالات Atlas إلى ما يقارب 15–30 بدل المئات.
  ② طبقة تخزين مؤقت مزدوجة للمسارات العامة السبعة (البث المباشر،
     الإحصائيات، الإعلانات، المشاركون، إعدادات المخيم، المقدّمون،
     الوسائط): كاش على حافة Vercel CDN (s-maxage 30–60 ثانية) بحيث لا
     تصل معظم الاستعلامات الدورية إلى قاعدة البيانات إطلاقاً، + كاش في
     ذاكرة الخادم داخل نفس النافذة الزمنية — استجابة أسرع وضغط أقل.
     الملفات الخاصة بالمستخدم (الإشعارات، لوحة التحكم، الأدمن) غير
     مخزّنة مؤقتاً إطلاقاً — بيانات كل مستخدم تظل حية ودقيقة كما هي.
  ③ تلطيف الاستعلام الدوري في الواجهة: بث النشاط 60←120 ثانية،
     عدّادات الإحصائيات 15←45، المشاركون 20←60، الإعلانات والمعرض
     30←90، شريط الإعلان 60←120، جرس الإشعارات 30←60 ثانية — مع
     توقّف كامل لاستعلام البث المباشر عند إخفاء التبويب. البيانات
     تظل محدّثة لأن صفحات العرض نفسها تعيد التحميل في كل تنقّل.
✔ ملاحظة: تعديلات الإدارة تظهر في الصفحات العامة خلال 30–60 ثانية
  كحد أقصى بسبب الكاش (لوحة الأدمن نفسها فورية دائماً).
✔ Protection de la limite de connexions MongoDB (le site est tombé
  car la limite Atlas a été dépassée) : pool par instance réduit
  15→5 avec fermeture des connexions oisives (30 s), cache CDN
  (s-maxage) + cache mémoire sur les 7 endpoints publics (le polling
  n'atteint presque jamais MongoDB), intervalles de polling adoucis
  côté client. Aucun changement visuel ou fonctionnel ; les données
  par utilisateur ne sont jamais mises en cache.

【 ملف .env — كل المفاتيح في مكان واحد 】

عدّل ملف .env مباشرة ثم أعد التشغيل (على Vercel/Railway: نفس
المتغيرات تُضاف في Settings → Environment Variables):
Modifiez directement le fichier .env puis redémarrez (sur Vercel/
Railway: mêmes variables dans Settings → Environment Variables):

1) قاعدة البيانات / Base de données:
     MONGODB_URI=mongodb://127.0.0.1:27017     (أو / ou MongoDB Atlas)
     MONGODB_DB=happy_inside_experience

2) حساب الأديمن / Compte administrateur:
     ADMIN_PHONE=0555555555
     ADMIN_PASSWORD=HappyInside@2026
     ADMIN_FULLNAME=مدير الموقع / Administrateur
   ✔ يُطبَّق فورًا حتى لو كانت القاعدة مهيأة سلفًا —
     غيّر الرقم/كلمة المرور وأعد التشغيل فقط.
   ✔ Synchronisé automatiquement à chaque démarrage,
     même si la base existe déjà.

3) مفتاح الجلسات / Secret des sessions:
     AUTH_SECRET=<مولَّد عشوائيًا / généré aléatoirement>
   ⚠ لا تشاركه مع أحد / ne le partagez jamais
     openssl rand -hex 48

4) أمان الكوكي / Sécurité du cookie (اختياري / optionnel):
     COOKIE_SECURE=true|false
   افتراضيًا آمن (Secure) في الإنتاج — اضبط false فقط للـ HTTP الذاتي.
   Secure par défaut en production — false uniquement en HTTP simple.

5) إشعارات Push / Notifications push (VAPID):
     VAPID_PUBLIC_KEY=<مولَّدة / générée>
     VAPID_PRIVATE_KEY=<مولَّدة / générée>
     VAPID_SUBJECT=mailto:contact@happyinside-experience.dz
   لإعادة التوليد / pour régénérer:
     npm exec -p web-push -- web-push generate-vapid-keys

6) معلومات التواصل (أول تهيئة فقط — ثم من لوحة التحكم):
   Contact (1er lancement uniquement — ensuite via le
   tableau de bord admin):
     WHATSAPP_NUMBER / CONTACT_EMAIL / FACEBOOK_URL / INSTAGRAM_URL

7) المساعد الذكي (اختياري — للنشر السحابي):
   Assistant intelligent (optionnel — déploiement cloud):
     AI_API_URL  = https://api.openai.com/v1   (أو Groq / OpenRouter)
     AI_API_KEY  = sk-...
     AI_MODEL    = gpt-4o-mini
   إن تُرك فارغًا يرد المساعد برسالة توضيحية لطيفة دون أخطاء.
   Si vide, l'assistant répond avec un message de repli gracieux.
